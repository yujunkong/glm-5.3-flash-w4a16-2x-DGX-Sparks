## P0 answer

Live TP=2 decode **never** calls `F.linear` with weight `(8192, 4096)`.

Rank 0 and rank 1: zero hits for that (N,K). The checkpoint tensors

```text
KDA q_proj / k_proj / v_proj  (8192, 4096)
```

are **not** separate GEMMs on this stack. They are packed into fused

```text
KDA in_proj_qkvbfg_a
M=8 N=12576 K=4096   (TP=2 local)
~305 calls ≈ 34 layers × 9 decode steps
```

kda.py forward is one `self.in_proj_qkvbfg_a(hidden_states)` then split. No q/k/v Linear.

N=12576 vs phase-6 microbench N=12480: TP=2 replicated `f_a`/`g_a` inflate the merged output
(q+k+v local 4096×3 + b 32 + f_a 128 + g_a 128 = 12576). Same fused op, slightly wrong N in P6.

## What N=8192 actually is (live)

The only F.linear with N=8192:

```text
MLA q_b_proj
M=8 N=8192 K=1536
prefix language_model.model.layers.{3,7,11,...,43}.self_attn.q_b_proj
stack  glm5next/attention.py:624 → mla.py:213 → ColumnParallelLinear
11 MLA layers × ~9 decode steps = 98 calls (plus 11 prefill M=28)
```

This is TP-sharded `q_b` (full unsharded is 16384×1536). It is **not** KDA q/k/v.

## Duplicate-projection question

Fused `in_proj N=12576` and unfused `q/k/v N=8192` do **not** both run.
The “fused인데 왜 N=8192가 따로 도나?” live answer: **it doesn’t.**
N=8192 on this path is MLA `q_b_proj` (K=1536), a different module.

Do not treat the P7 20.5% bucket as wasted KDA q/k/v recompute. That hypothesis is rejected.
